# Assets, service desk and laboratory mapping (FR21–FR23)

## Asset model

Stable asset UUID and unique organisational asset number, category, manufacturer/model/serial, acquisition/warranty dates, firmware, status/condition, owning site, location, allocated user/workstation, verification dates and maintenance history. Categories include workstation, monitor, storage (lab-owned), forensic write blocker, licence dongle, mobile extraction equipment, adapter/cable, spare hardware. Exclude forensic exhibits and attached evidential devices. Hardware observations are distinct from authoritative registered assets: match by trusted identifiers and reviewed reconciliation; duplicate/blank serials or replacement motherboard must not silently merge records. Discover permitted peripherals only, redact identifiers outside asset role. Manual register and reconcile devices not reliably detectable, including write blockers; no automatic claims of correct operation from USB enumeration.

Lifecycle: draft → available → allocated/in service → damaged/missing/quarantined/repair → available or retired; authorised transitions only, reason and append-only events, no automatic disposal. Transfers use effective dated assignment history and concurrency checks; preserve previous location. Warranty/verification reminders configurable; links to verification/repair reports and optional approved attachments; no assertion of calibration or accreditation. QR codes contain opaque asset ID or approved internal app link only, no credentials or personal info; scans require login and scope, print/export audited; no public endpoint. Labels remain valid after relocation, revoke retired labels if necessary.

## Service desk

One ticket model with type technical fault, missing equipment, damaged equipment, equipment request or software request. Fields: ticket ID, reporter, site, device/asset optional, requested category/quantity, severity, description, status, assignee, timestamps, history, resolution and approved attachment refs. Requester sees own tickets; support queue scoped by site/assignment; asset/quality approvers separate. User can submit equipment requests without existing asset ID. Missing/damaged reports flag asset for review, do not automatically retire or alter availability until custodian confirms; urgent damaged write blocker can trigger quarantine recommendation. Workflow: submitted → triaged → assigned/in progress → waiting requester/approval → resolved → closed/reopened; request approval/rejection and allocation tracked separately, no automatic purchase. Equipment allocation reserves available asset transactionally; concurrency prevents double allocation; partial fulfilment tracked. Software request routes to catalogue owner, not direct install permission.

Diagnostic bundle: explicit opt-in preview, removable fields, device-bound timestamp and provenance. Allowlisted OS/build, hardware summaries, disk free space, approved software inventory subset, health event codes, agent version/state, driver info and recent bounded metrics; never raw event logs, memory dumps, screenshots, case names, paths, passwords, tokens or process arguments. Ticket free text warns against evidence/personal data. Attachments restricted size/type, quarantine and malware screening via approved internal workflow, random storage keys, no executable content, authorised download and retention; if scanner unavailable fail closed or disable attachments. No external upload. Offline drafts local per-user protected store; submit after reauth, idempotent; don't claim sent until persisted. Assignment, comments, escalation, resolution and updates use existing durable notifications; user acknowledgement not resolution. Retention approved by data owner; audit exports redact sensitive text by default.

## Laboratory map

Site → building → floor → room/zone; map revision and background asset, normalized coordinates (0..1), orientation, optional dimensions and position labels. Upload PNG/JPEG only initially, size/pixel cap, validate/decode/re-encode on trusted host; no SVG scripts, external references or embedded metadata. Optional native drawing grid, drag/drop, pan/zoom, snap, keyboard placement and list equivalent; WinUI/Win2D candidate subject to licence/compatibility check. Map editors limited to location scope; preview and optimistic concurrency save, immutable revision/history and undo as new revision. Multiple floors and rooms; workstation/registered equipment placements, unplaced asset queue, no duplication across active maps without explicit alias. Live status overlays derived from authorised API state: online/stale/offline, protected/confirmed processing, health severity, compliance, asset condition, allocated/unallocated; stale timestamps and text/icon alternative. No evidence location or staff live tracking. Selection opens existing detail view, Wake/RDP only through separate authorised actions. Floor plans sensitive; scoped upload/view/export, no public sharing. Never infer device location from IP alone.
