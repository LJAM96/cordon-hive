# Forensic operations monitoring (FR26)

## Adapter boundary

Use existing Hive.Agent/Hive.Windows, Hive.Contracts and protection lock model. Registry of approved adapters per product/version, capability flags, source, schema version, polling budget, signed/approved code and config. Begin with generic process presence and explicit manual protection; then first-party Cordon SDK for Sift/Desktop/Capture/Relay/Scan/USB as applicable, then vendor-documented APIs or allowlisted local structured log adapters only after product-specific verification and licence review. No assumptions that Cellebrite, Magnet, X-Ways or other vendors expose progress APIs; do not scrape UI, capture windows, inject DLLs, read process memory, access case files or upload raw logs. Parse only permitted status fields locally; never transfer filenames, exhibit IDs, paths, case reference, extracted content, credentials or command lines. Adapter failures isolated, bounded retry, no effect on forensic app.

## Semantics

Operation record: opaque locally generated operation ID, device certificate identity, adapter/product/version, operation type (imaging, extraction, processing, indexing, classification or other approved enum), status, confidence/source, start/last update/end UTC, optional progress 0..100 and nullable ETA seconds with methodology, safe error category, protection lease reference and monotonic sequence. Process present = detected, not a confirmed job. Resource activity = inferred, never proof of operation, success or stall. Confirmed status comes from trusted first-party/vetted vendor signals or user declaration explicitly marked. State detected/inferred/confirmed running/paused/completed/failed/cancelled/unknown; transitions validated per adapter, terminal states immutable except explicit correction event. Multiple simultaneous jobs supported; boot/session changes and stale observations handled explicitly. No synthetic percent/ETA; ETA only from reliable vendor estimate or calibrated progress model, reset on phase change; display confidence. Stale signals become unknown, not completed. Stall alert only for supported progress semantics with configurable timeout and heartbeat, suppress during known pause; otherwise "status unavailable". Completion/failure notification only from confirmed terminal event, dedup by operation ID + sequence; source cannot complete another source's action.

## Safety

First-party SDK uses authenticated local IPC, publisher registration scoped to approved application and own operations/locks, bounded DTOs and explicit release; no new inbound endpoint, no arbitrary code. Protect before work begins where cooperative; local guard independent of connectivity. Unknown/stale protection blocks disruptive maintenance and assisted RDP under existing rules. Never auto-release lock merely because ETA passes, application idle, heartbeat absent or server restarts; reconcile with local source and authorised manual release. Vendor adapters that cannot establish safe state remain manual-only for disruptive actions. No remote start/stop of forensic jobs in this scope. Dashboard scoped to site, shows active/protected/unknown and history, user-visible notices, retention policy separate from case evidence. Benchmark and deployment share workload guard and mutex. Test with synthetic workloads, no evidence data; adapter capability matrix per version and quality approval before enabling.
